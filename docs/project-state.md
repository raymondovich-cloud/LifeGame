## 1. Где остановились

На текущем этапе завершён фундамент веб-версии LifeGame и остановлена разработка финансового индекса на согласованной методике.

Последнее согласованное состояние:

1. Авторизация и регистрация работают как отдельный Identity-контур.
2. После авторизации пользователь не должен автоматически попадать в Profile.
3. Текущий модуль по умолчанию — Finance.
4. Profile доступен как отдельная вкладка только авторизованному пользователю.
5. Finance содержит 6 блоков.
6. Блок 06 — «Индекс финансовой стабильности» находится в слое `source/index/finance`, а не в `source/domain/finance`.
7. Для индекса зафиксирована методика **ИФС-1000**.
8. Блок 03 «Финансовая нагрузка» расширен для хранения одновременно:
   - общей суммы долга;
   - регулярного платежа.
9. Эти две величины используются индексом независимо:
   - сумма долга → P₁;
   - регулярный платёж → P₃.
10. На этом этапе разработка остановлена.

# 10. ИФС-1000

Каноническая формула находится исключительно в:

`source/index/finance/finance.index.js`

Это принципиально.

**Индекс не находится в:**

`source/domain/finance`

---

## ИФС-1000

Индекс финансового состояния переводит личные финансы в шкалу:

**0–1000**

Формула:

**ИФС = P₁ + P₂ + P₃ + P₄ + P₅**

Каждый показатель:

**0–200**

### P₁ — Активы / имущественный баланс

Активы − общая сумма долгов и кредитов.

Если результат > 0:

**200**

Если результат ≤ 0:

**0**

---

### P₂ — Фактически заработано

`((Доход / Расходы) − 1) × 200`

Ограничение:

**0–200**

---

### P₃ — Финансовая нагрузка

`(1 − Платежи / Доход) × 200`

Ограничение:

**0–200**

---

### P₄ — Контроль трат

Кредитные платежи сюда не входят.

`(1 − Расходы / Доход) × 200 × 2`

Ограничение:

**0–200**

---

### P₅ — Финансовая подушка

`((Подушка / Расходы) / 6) × 200`

Максимум:

**200**

---

# 11. Эталонный расчёт ИФС

Зафиксированный демонстрационный пример:

| Компонент | Баллы |
|---|---:|
| P₁ | 200 |
| P₂ | 133 |
| P₃ | 160 |
| P₄ | 160 |
| P₅ | 100 |
| **ИФС** | **753 / 1000** |

Результат:

**753 — Финансовое благополучие**

Диапазоны:

- **0–400** — критическое состояние;
- **410–700** — неустойчивое состояние;
- **710–1000** — финансовое благополучие.

# 12. Связь блока 03 с ИФС

Это последнее важное архитектурное решение.

Блок 03 «Финансовая нагрузка» является единым источником долговых обязательств.

Из каждой записи можно получить:

### Для P₁

`debt`

Общая сумма задолженности.

### Для P₃

`payment`

Регулярный платёж.

Например:

**Ипотека**

- долг: 4 000 000 ₽;
- платёж: 30 000 ₽/мес.

Тогда:

- P₁ использует 4 000 000 ₽;
- P₃ использует 30 000 ₽.

**Эти величины нельзя смешивать.**

**Domain → Core Event → Application/Adapter → Memory/Storage**

# 10. Finance / Assets — зафиксированная семантика (05.10.2026)

Первый блок Finance теперь называется **«Активы»**.

Он предназначен для учёта имущественной и финансовой позиции пользователя, а не только денег, доступных немедленно.

Примеры записей:

- квартира;
- автомобиль;
- наличные;
- банковский счёт;
- средства на карте;
- другие активы пользователя.

Каждый актив имеет стоимость и признак ликвидности. По умолчанию новый актив создаётся как ликвидный; пользовательский интерфейс позволяет явно выбрать «Ликвидный актив» или «Неликвидный актив».

**Критическое правило:** общая стоимость активов не равна ликвидным средствам. Недвижимость или автомобиль могут входить в общий имущественный баланс, но не должны автоматически увеличивать ресурс, доступный для немедленного покрытия расходов.

Технические контракты первого блока Finance переведены с `liquid-funds` на `assets`:

- `source/domain/finance/assets/assets.js`;
- `source/memory/finance/assets.memory.js`;
- `source/presentation/finance/assets.statistics.js`.

Старые файлы `liquid.funds*` удалены как устаревшие.
