# LifeGame — текущее состояние проекта

**Статус:** CURRENT  
**Дата аудита:** 06.10.2026  
**Репозиторий:** `raymondovich-cloud/LifeGame`  
**Основная ветка:** `main`

> Этот документ отражает фактическое состояние проекта на момент последнего аудита. Зафиксированная BASELINE хранится отдельно в `docs/fixed-version-project.md`.

---

## 1. Архитектура

В проекте используются следующие слои:

- `core/`;
- `domain/`;
- `application/`;
- `presentation/`;
- `infrastructure/`;
- `memory/`;
- `index/`;
- `design/`.

`design/` является независимой Design System.

Текущая архитектура сохраняет следующие границы:

- Domain не должен напрямую обращаться к Memory, Infrastructure, UI и хранилищам;
- Application координирует прикладные сценарии;
- Presentation отвечает за UI и пользовательское взаимодействие;
- Infrastructure содержит технические реализации;
- Memory отвечает за состояние и историю;
- Index содержит расчётные показатели;
- Design System отделена от бизнес-логики.

## 3. Identity

Identity реализован как отдельный контур с разделением Domain, Application, Infrastructure и Presentation.

Supabase используется как текущая техническая реализация Identity/хранилища.

В репозитории присутствуют:

- Supabase Auth;
- PostgreSQL;
- RLS;
- private security events;
- Identity migration `supabase/migrations/0001_identity_foundation.sql`.

Текущая документация не должна трактовать Identity как исключительно планируемый функционал без дополнительной проверки.

## 4. Finance

Finance DATA содержит шесть блоков:

1. **Активы**;
2. **Фактически заработанно**;
3. **Финансовая нагрузка**;
4. **Обязательные траты**;
5. **Финансовая подушка**;
6. **Индекс финансовой стабильности**.

Finance Main и Finance DATA являются разными пользовательскими поверхностями и не должны смешиваться.

### Assets

Первый блок называется **Assets / Активы**.

Актив имеет стоимость и признак ликвидности:

- `liquid`;
- `illiquid`.

Общая стоимость активов считается отдельно от ликвидных и неликвидных активов.

Активы не должны автоматически трактоваться как деньги, доступные для немедленного расходования.

Текущая реализация использует:

- `source/domain/finance/assets/assets.js`;
- `source/memory/finance/assets.memory.js`;
- `source/presentation/finance/assets.statistics.js`.

### Financial burden

Финансовая нагрузка различает:

- `debt` — общую задолженность;
- `payment` — регулярный платёж.

Эти значения используются раздельно.

## 5. Financial Stability Index

Текущая реализация использует **FSI 2.1**.

Расчёт находится в:

`source/index/finance/finance.index.js`

Текущая реализация возвращает:

- значение индекса;
- версию `2.1`;
- категорию;
- компоненты расчёта;
- диагностические показатели.

В проектной документации утвержденное обозначение финансового индекса — **IFS 2.1**.

Старое обозначение **ИФС-1000** в качестве текущего состояния не используется и относится к устаревшей исторической документации.

## 7. Memory и аналитика

Finance использует Memory для состояния и исторических snapshots.

В проекте присутствуют отдельные Application-модули аналитики Finance и Assets.

Аналитика работает с временными диапазонами и snapshots; конкретное поведение должно подтверждаться соответствующими тестами и текущим кодом.
