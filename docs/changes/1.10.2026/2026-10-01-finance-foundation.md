# Изменение: каркас Finance и UX-контракт подблоков

**Дата и время:** 1 октября 2026 года, 07:35:31 MSK (UTC+03:00)

## Изменённые файлы

- `docs/agent.md` — Version 1.7 → Version 1.8
- `source/domain/finance/liquid.funds/liquid.funds.js` — Version 1.0 → Version 1.1
- `source/domain/finance/actual.earnings/actual.earnings.js` — Version 1.0 → Version 1.1
- `source/domain/finance/financial.burden/financial.burden.js` — Version 1.0 → Version 1.1
- `source/domain/finance/mandatory.expenses/mandatory.expenses.js` — Version 1.0 → Version 1.1
- `source/domain/finance/financial.cushion/financial.cushion.js` — Version 1.0 → Version 1.1

## Что изменено

В `docs/agent.md` добавлен единый UX-контракт для подблоков:

1. Подблок раскрывается и скрывается нажатием.
2. Редактируемая строка открывает редактирование продолжительным нажатием.
3. Удаление строки выполняется свайпом влево по паттерну iOS 26.

Дополнительно зафиксировано архитектурное разделение: обработка жестов и состояния UI остаются в UI/Application-слое, а Domain не зависит от DOM, CSS и платформенных API.

В пяти существующих заготовках Finance создан минимальный доменный каркас:

1. Ликвидные средства — `liquid.funds`
2. Фактически заработано — `actual.earnings`
3. Финансовая нагрузка — `financial.burden`
4. Обязательные траты — `mandatory.expenses`
5. Финансовая подушка — `financial.cushion`

Каждая категория теперь имеет:
- стабильный идентификатор;
- номер категории;
- английское системное имя;
- русское отображаемое имя;
- начальный state с массивом `entries`.

## Архитектурное решение

На этом этапе намеренно не добавлялись расчёты, хранение, DOM-логика, обработчики жестов или визуальная стилизация.

Каркас Finance остаётся независимым от UI и инфраструктуры. Дальнейшая функциональность будет добавляться поверх этих границ отдельными ответственностями.

## Причина изменения

Подготовить Finance к последовательной реализации функционала, одновременно закрепив единый UX для всех будущих подблоков приложения.

## Итоговый статус

**Завершено.**

Каркас пяти основных категорий Finance создан, а обязательный UX-контракт подблоков зафиксирован в архитектурных правилах проекта.
