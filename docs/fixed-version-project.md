# LifeGame — Fixed Version Project

**Статус документа:** BASELINE  
**Дата фиксации:** 06.10.2026  
**Назначение:** хранить только явно зафиксированные пользователем этапы и состояния проекта.

## 1. Правило документа

Этот документ не является Current state и не заменяет проверку фактического кода и тестов.

Он фиксирует только то, что было явно закреплено как рабочая основа проекта. Если текущий код изменился после фиксации, документ не обновляется автоматически.

Для определения текущего состояния используются актуальные код, тесты и другие источники проекта в соответствии с `docs/agent.md`.

## 2. Зафиксированная базовая система

На 06.10.2026 явно закреплены:

- Clean Architecture как архитектурная основа;
- шесть функциональных слоёв: `core`, `domain`, `application`, `presentation`, `infrastructure`, `memory`;
- отдельная независимая Design System в `source/design`;
- запрет Domain на хранение пользовательских данных и прямую зависимость от Memory;
- Application как слой координации между Domain, Memory, Index и UI;
- разделение пользовательских и системных данных;
- Security как архитектурная часть системы;
- Finance как Module 01 и стартовый модуль приложения;
- пользовательские модули Finance, Health, Development и Profile;
- разделение Finance Main и Finance DATA;
- шесть блоков Finance DATA:
  1. Активы;
  2. Фактически заработанно;
  3. Финансовая нагрузка;
  4. Обязательные траты;
  5. Финансовая подушка;
  6. Индекс финансовой стабильности;
- семантика Assets как имущественных и финансовых активов, а не только ликвидных средств;
- разделение `debt` и `payment` в финансовой нагрузке;
- единая dark-first Design System;
- сохранение согласованных CRUD и пользовательских взаимодействий;
- обязательное документирование изменений и версионирование файлов.

## 3. Что означает фиксация

Зафиксированное состояние является BASELINE для дальнейшей разработки.

Это не означает:
- что каждый пункт является полностью реализованным;
- что BASELINE автоматически совпадает с текущим кодом;
- что будущие изменения запрещены.

Любое изменение зафиксированной основы должно быть осознанным и согласованным в соответствии с `docs/agent.md`.

## 4. Связь с другими документами

- `docs/agent.md` — нормативные правила проекта;
- `docs/fixed-version-project.md` — явно зафиксированная базовая точка;
- текущий код и тесты — источник фактического CURRENT состояния;
- `docs/changes/` — история изменений по пользовательским запросам;
- `docs/sessions/` — контекст отдельных рабочих сессий;
- `docs/project-state.md` — отдельный документ текущего состояния, требующий самостоятельного аудита.
